## 一、开源抽卡概率库 / 工具生态

### 1.3 GGanalysis 没做、但被其它项目做了的能力

Web 交互 UI、**Cashback 剩余抽数返还期望**、用户真实抽卡记录导入与个性化分析、真实大样本校准 pity 曲线、跨阶段预算规划 UI、多游戏统一对比视图、尾部风险量化(VaR/CVaR)、可复现+可解释 trace、PRNG 级真实性模拟、DP/MC 双引擎互验。

> 结论：GGanalysis 在"精确分布+多游戏建模"是天花板；差异化空间在 **数据导入(UIGF)、规划向指标(Cashback/风险)、跨游戏统一比对、可视化**——这些没有任何单一项目全做齐。

### 2.2 🔴 UIGF / SRGF 统一数据格式（务必支持，之前遗漏）

由 [UIGF-Org](https://uigf.org) 维护的社区标准，让抽卡记录能跨应用/跨游戏/跨账号互导。

**版本演进**：UIGF v2-3（仅原神）→ SRGF（星铁，已弃用）→ **UIGF v4.0**（合并 SRGF + 加绝区零，不向下兼容）→ v4.1（星铁3.4）→ **v4.2（当前，加千星奇域）**。

**v4.2 JSON 结构核心**：
```json
{
  "info": {"export_timestamp": 1700000000, "export_app": "...", "export_app_version": "1.0.0", "version": "v4.2"},
  "hk4e":  [ {"uid": "...", "timezone": 8, "lang": "zh-cn", "list": [/*原神记录*/]} ],
  "hkrpg": [ {"uid": "...", "timezone": 8, "list": [/*星铁记录*/]} ],
  "nap":   [ {"uid": "...", "timezone": 8, "list": [/*绝区零记录*/]} ]
}
```
- 顶层按游戏代号分区：`hk4e`(原神)/`hkrpg`(星铁)/`nap`(绝区零)。
- 每条记录字段：`uigf_gacha_type`(归并相同保底逻辑的池子)、`gacha_type`、`item_id`、`count`、`time`、`name`、`item_type`、`rank_type`、`id`。
- **关键陷阱**：`time` 保留原始字符串**不要转 Date**（时区会算错 pity 顺序）；pity 排序用 `id` 而非本地时间；`version` 匹配 `^v\d+\.\d+$`；字段类型要严格（官方有 JSON Schema 可校验）。
- UIGF-Org 要求"支持某游戏须同时实现导入+导出"。

> **决策含义**：UIGF v4.2 应作为工具的一等公民数据入口——接收 paimon/HoYo.Gacha 等导出、也能导出回去，零成本接入整个数据生态，且不碰游戏接口。

### 2.3 authkey 抽卡链接机制（数据如何产生 / 为何不封号）

- 游戏内打开"抽卡历史"时，本地日志(PC: `output_log.txt`)会写入带 `authkey` 的 URL；脚本读取后请求米哈游 `getGachaLog` 接口分页拉取。
- **authkey 安全属性**：只读、24h 过期、不含登录凭证、不改内存不注入 → **不违反 ToS、不封号**（须向用户说明，区别于 Cookie 登录/外挂）。
- ⚠️ 接口路径随版本变动（如 4.6 改过路径），脚本需长期维护——**故应以 UIGF 文件为主、authkey 抓取为辅/可选**。

### 2.4 玩家最高频功能（按使用频率）

1. 当前保底数 / 距硬保底还差几抽（最高频）
2. 抽卡记录导入与历史统计（pity 均值、50/50 胜率、终身抽数）
3. 运气分位 / 全服对比（情感钩子、传播主力）
4. "我有 N 资源/想要某角色，概率/期望多少"（决策核心）
5. 预算规划（攒多少够下一个）

### 2.5 优秀可视化范例

- "距保底还有 X 抽"大数字 + 进度条（paimon）
- 运气百分位 + 全服分布直方图标"你在这里"（SRS）
- 累积概率曲线（横轴抽数、纵轴把握度）（Hu Tao/sakan）
- 预算换算表（目标→抽数→货币）（pitycalculator）
- 互动抽卡模拟器（gachastrategy）

## 三、跨游戏经济比对方法论

### 3.1 已有研究

- **业界权威**：Naavik《Dissecting HoYoverse's Newest Gacha Engine》—— 米哈游三游"同一台抽卡引擎"，单抽 ≈ **$2**、保底一致、5★ 0.6% 一致，可做无偏对比。
- 中文社区主力形态：**每版本"能攒多少抽"逐项拆解**（日常/活动/终局/月卡/前瞻码）。
- 学术界主要研究**心理与监管**（ScienceDirect/Southampton/Uppsala），几乎无"跨游戏性价比量化模型"——量化由玩家社区主导。
- **机会**：现成内容几乎都局限在米哈游三游内部；拉入明日方舟/鸣潮做真正跨厂商归一化，市面上几乎没有严谨成果 → **差异化空间**。

### 3.2 归一化指标（SUoV = "一个限定"为单位）

| 层级 | 指标 | 说明 |
|---|---|---|
| ①概率 | **期望抽数/限定一个** | 必须含 软硬保底+50/50+UP权重，**不能比基础出率** |
| ②货币 | 期望货币/限定一个 | = 期望抽数 × 每抽货币 |
| ③现金 | 折算人民币/美元/限定一个 | 统一用"最高性价比常规档位"，建议排除首充双倍 |
| ④速率 | 每30天白嫖抽数 | 统一成 抽/30天（版本长度不同）|
| ⑤综合 | 白嫖每年可得限定数 = 年白嫖抽数 ÷ 期望抽数 | 终极"慷慨度" |
| ⑥频率 | 产出÷需求 = 年白嫖限定数 ÷ 年新增限定数 | 是否追得上版本 |

### 3.3 各游戏关键经济参数（附来源见调研记录）

| 游戏 | 每抽货币 | 最高稀有度 | 基础出率 | 软保底 | 硬保底 | 平均出货 | UP机制 |
|---|---|---|---|---|---|---|---|
| 原神 | 160 原石 | 5★ | 0.6% | 74 | 90 | ~62抽 | 50/50；5.0起捕获明光→限定综合55%；武器池0.7%，定轨1命定值(≤130抽) |
| 星穹铁道 | 160 星琼 | 5★ | 0.6% | 74 | 90 | ~62抽 | 50/50；光锥0.8% |
| 绝区零 | 160 菲林 | S级 | 0.6% | 74 | 90 | ~62抽 | 50/50；音擎1.0%必出当期；邦布池仅游戏内券 |
| 鸣潮 | 160 星声 | 5★ | 0.8% | ~66 | 80 | ~55-62抽 | 角色50/50；武器无50/50必出当期 |
| 明日方舟 | 600 合成玉 | 6★ | 2% | 51(每抽+2%) | 99 | 任意6★~34抽 | **2%是"任意6星"被UP稀释**；限定300井；常驻150/300选调 |

- 米游档位：顶档 ≈ $1.98/抽，首充双倍 ≈ $1.23/抽，业界统一口径 ≈ **$2/抽**。
- 白嫖产出(零氪/版本)：原神~76、星铁~84、绝区零~67、鸣潮~75-100、方舟~60-70/月。

### 3.4 🔴 8 个不可比的坑（务必处理）

1. **基础出率不可直接比**：方舟 6★2% 看似>米游0.6%，但货币尺度不同(600vs160) + **2%是"任意6星"被UP权重稀释**，抽"指定那个"期望远高于35抽。
2. **保底结构不同**：米游/鸣潮 50/50+跨池继承；方舟 概率爬坡+6星跨池累计+300井；原神5.0还有捕获明光。
3. **限定 vs 常驻**：只比限定（常驻可兑换/随时抽）。
4. **角色 vs 武器/光锥/音擎**：武器池出率/保底/是否50/50各异 → 分"出货"与"满配"两档。
5. **队伍构成差异**：绝区零3角色+1邦布 vs 米游4角色，五星需求量不同。
6. **新手一次性福利 vs 长期产出**：不可重复，须分开，否则高估新游。
7. **版本长度/产出口径不一致**：统一"抽/30天"并标注口径(±15%误差)。
8. **货币现金档位结构差异**：$2/抽只对米游成立；方舟用"元/抽(按最优礼包)"；汇率固定基准。

## 四、概率论建模方法

### 4.1 精确方法分工（数学等价，擅长面不同）

- **DP / 状态机**：引擎主力，输出完整 PMF。状态=(水位, 已得目标数[, 带记忆机制的额外维度])。
- **卷积（+FFT）**：多目标/多池组合（A*B = 两随机变量之和；A**n = 抽 n 个拷贝）。GGanalysis 核心。
- **吸收马尔可夫链**：闭式校验。期望 = N·1（N 为基本矩阵），方差 B=N(2N−I)−... 等。
- **蒙特卡洛**：兜底 + 交叉验证，报告置信区间。

### 4.2 关键数学结论

- **软保底反推是欠定问题**：单凭公示综合概率(1.6%)无法唯一确定每抽概率曲线，必须叠加**经验出货分布做形状约束**（优化反演 / 平稳分布两条路径）。→ 我们直接采用社区公认参数即可，不必重新反推。
- **经验概率 vs 条件概率**：做正确图表必须区分"长期平均出率"与"每一抽的真实条件概率"——后者才是软保底曲线。
- **捕获明光等带记忆机制**：必须给 DP 加"**连歪计数**"维度；**卷积法在此失效**。→ 这是自研 reference 引擎相对 GGanalysis 卷积法的潜在增量。
- **50/50 大保底**：限定 UP 期望 ≈ 1.5 × 单次出金期望 ≈ **93 抽**。
- 多拷贝：抽 k 个 = 负二项 / 自卷积；集齐多种道具 = coupon collector。

### 4.3 进阶视角（加分项）

- **尾部风险**：VaR/CVaR、偏度——"留 80-90 抽安全垫"的最坏情况思维（MDPI 2026）。
- **最优停止/期望效用**：什么时候该停手——学术上有 loot box 最优停止研究。

### 4.4 "必备计算 × 最佳方法"清单

| 计算 | 最佳方法 |
|---|---|
| 单目标完整 PMF/CDF | DP / 卷积（GGanalysis）|
| 期望/方差/分位数 | 从 PMF 派生 |
| 多拷贝（满命/精炼）| 自卷积 |
| 角色+武器组合 | 卷积 A*B |
| N 抽内概率 / 达 X% 把握所需抽数 | CDF 反查 |
| 捕获明光精确 | DP + 连歪计数维度（非卷积）|
| Cashback 剩余抽数 | DP / 模拟 |
| 尾部风险 VaR/CVaR | 从 PMF 派生 |
| 兜底校验 | 蒙特卡洛 + 置信区间 |
