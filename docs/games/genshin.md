# 原神（Genshin Impact）抽卡机制事实卡

> 用途：作为建模的「事实来源」。数值为社区基于大规模实测（genshin-wishes.com 2021 年已 2500 万抽）逆向得出，与官方公示综合概率一致。
> **软保底精确算法官方从未公布**；满足「无穷抽收敛到官方概率 + 拟合实测分布」的模型不唯一，本项目采用社区公认参数。

### 联动池 / 双限定（uigf_gacha_type 400）

联动角色池与常规角色活动祈愿（301）**共享保底**，无独立概率模型；历史还原时 301 与 400 合并计入角色池（见下方 UIGF 策略）。分析层仍使用 `character` banner + `up_5star_character`。

> 所有「已验证」均指适配层输出与 GGanalysis 对应模型逐点一致（误差 < 1e-12）。

### 真实记录还原策略（UIGF history）

`io/history` 通过 `GameSpec.history_policy`（`games/base.HistoryPolicy`）读取原神的还原规则，保持 game-agnostic：

- **301/400 合池**：角色活动祈愿 UIGF 同时使用 `uigf_gacha_type` 301（常规）与 400（双限定），二者共享保底，故均归入角色历史（实现同时检查 `uigf_gacha_type` 与 `gacha_type`，避免某条 400 缺字段被排除）。
- **50/50 判定**：抽到「常驻 5★」（`STANDARD_5STAR_CHARACTERS`，含中英文名）即判为歪了→大保底，并按捕获明光模型累加连歪计数。
- **语言可靠性**：仅 `zh-cn`/`en` 的名字能匹配常驻集合；其它语言的记录会发出告警提示「50/50 判定可能不准」，避免静默误判。

### 捕获明光（Capturing Radiance）建模

- 是「带记忆」的条件概率机制：连续歪的次数决定下次 50/50 转 UP 的概率。
- GGanalysis 0.4.2 采用的推测表 `CR_PITY = [0, 0.5, 0.55, 0.95, 1]`，即连歪 k 次时下个 5★ 为 UP 的概率：
  - 连歪 0 次 → 0.50（普通 50/50）
  - 连歪 1 次 → 0.55
  - 连歪 2 次 → 0.95
  - 连歪 3 次 → 1.00（必为 UP，不会连歪第 4 次）
- 与硬保底/大保底独立：捕获明光只改变「50/50 失败时的结果」，不影响保底计数。
- **对单个拷贝影响极小**（大保底已托底），对**多拷贝**影响明显（拷贝间会累积连歪）。

### 已实测核对（GGanalysis 0.4.2，见 DECISIONS.md D18）

- 单个 5★（不分 UP）平均：**62.30 抽**
- 1 个 UP 5★ 期望：**93.45 抽**（≈ 1.5 × 62.3）
- 抽 3 个 UP：新模型 **271.7 抽** < 旧 50/50 **280.3 抽**（捕获明光增益）

## 武器活动祈愿（Weapon Event Wish）

| 机制 | 数值 |
|---|---|
| 5★ 基础概率 | 0.7% / 抽 |
| 5★ 软保底起点 | 第 63 抽起每抽 +7% |
| 5★ 硬保底 | 第 80 抽 |
| UP 概率 | 75% 当期 / 25% 常驻；歪则下个 5★ 必为当期 |
| 定轨（Epitomized Path, 5.0+）| 命定值为 1，最多 130 抽必出选定 UP 武器 |

> **与星铁/绝区零武器池的区别**：原神使用 `up_5star_ep_weapon`（EP 定轨 + 75/25）；星铁光锥 / 绝区零音擎使用 `up_5star_weapon`（经典 75/25，无定轨）。
